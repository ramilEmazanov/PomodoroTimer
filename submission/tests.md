# Клиентские тесты Pomodoro Timer

## Цель и связь с заданием

Проверки добавлены для критериев № 7–10 из [task.md](../task.md):

- **№ 7 — защита от повторных действий:** двойной клик, повторный Enter и попытки запуска Recents во время активной сессии.
- **№ 8 — отображение компонентов и взаимодействия:** главная страница, переход к таймеру, выбор и ввод длительности, нажатия кнопок, открытие и закрытие диалога сброса.
- **№ 9 — валидация формы:** обязательные значения, отрицательные и дробные числа, превышение диапазона, нулевая длительность, сообщения об ошибках и исправление ввода.
- **№ 10 — состояния интерфейса (частично):** пустые и заполненные Recents, успешное завершение отсчёта, ошибка ввода и восстановление после неё. Загрузка и подмена ответов сервера не покрыты: приложение синхронно читает `localStorage` и не использует API.

В текущем приложении нет API, отправки формы на сервер и ожидания ответа: таймер запускается синхронно в браузере. Поэтому проверяется защита от повторного запуска локального отсчёта. Эти тесты не подтверждают отсутствие второго HTTP-запроса во время ожидания сервера; для такой интеграции потребуется отдельная проверка с задержанным тестовым ответом и подсчётом запросов.

## Инструменты и подготовка

- [src/App.test.tsx](../src/App.test.tsx) — три теста реального приложения.
- [src/App.interactions.test.tsx](../src/App.interactions.test.tsx) — 11 тестов отображения компонентов и взаимодействий, включая параметризованные случаи работающего и приостановленного таймера.
- [src/App.validation.test.tsx](../src/App.validation.test.tsx) — 15 тестов валидации длительности и исправления ошибок.
- [src/App.states.test.tsx](../src/App.states.test.tsx) — 8 тестов состояний с контролируемыми локальными данными и ошибками хранилища.
- [config/vitest.config.ts](../config/vitest.config.ts) — конфигурация Vitest и окружения jsdom.
- [src/test/setup.ts](../src/test/setup.ts) — подключение DOM-проверок и очистка после тестов.
- React Testing Library и user-event — поиск элементов по доступным названиям, клики, ввод и нажатия клавиш.

Приложение рендерится в `StrictMode`. Перед каждым тестом очищается `localStorage` и выбирается светлая тема. В проверках повторного запуска подготавливаются две записи Recents: 1 и 2 минуты, затем через Timer → Input задаётся длительность 1 минута. Проверки взаимодействий начинают с пустого Recents; для теста выбора недавнего таймера отдельно подготавливаются записи на 1 и 2 минуты. Для диалогов через интерфейс задаётся длительность 30 секунд, для завершения при открытом диалоге — 3 секунды.

Используются виртуальные часы для `Date`, `setInterval` и `clearInterval`: тесты продвигают отсчёт без реального ожидания. React-компоненты и логика таймера не подменяются. Наблюдение за `setInterval` дополнительно проверяет, что при первоначальном запуске создаётся один интервал; основная проверка результата — время, отображаемое в интерфейсе.

### Валидация длительности — 15 тестов

В режиме Input поля Hours, Minutes и Seconds обязательны; значение `0` допустимо для отдельного поля. Часы принимают целые числа от 0 до 23, минуты и секунды — от 0 до 59. Общая длительность должна быть положительной: от 1 секунды до `23:59:59`.

| Проверка             | Ввод и действия                                                                 | Ожидаемый результат                                                                                                                                                                                                                                                                                | Число случаев |
| -------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| Обязательные поля    | Поочерёдно очистить Hours, Minutes или Seconds                                  | Поле остаётся пустым, получает `required` и `aria-invalid`. Видно сообщение `Enter a value for Hours.` либо соответствующее сообщение для другого поля; оно связано с полем через `aria-describedby`. Start и Enter не запускают таймер. После ввода `1` ошибка исчезает и таймер можно запустить. | 3             |
| Некорректные числа   | Для Hours передать `-1`, `24`, `1.5`; для Minutes и Seconds — `-1`, `60`, `1.5` | Неверное значение остаётся в поле для исправления. Видно сообщение о целом числе и диапазоне, например `Hours must be a whole number from 0 to 23.`. Запуск кнопкой и Enter заблокирован, отсчёт и запись Recents не появляются. После замены значения на `1` ошибка исчезает и Start доступна.    | 9             |
| Нулевая длительность | Кнопкой Cancel обнулить все поля                                                | Видно `Choose a duration of at least 1 second.`, запуск заблокирован. После ввода 1 секунды сообщение исчезает и Start запускает `0:01`.                                                                                                                                                           | 1             |
| Допустимые границы   | Ввести `00:00:01` и `23:59:59`                                                  | Ошибок нет, Start запускает таймер с точным введённым временем.                                                                                                                                                                                                                                    | 2             |

Очистка, исправление, нажатия кнопок и Enter выполняются через user-event. Для девяти некорректных числовых значений используется `fireEvent.change`: он передаёт целое ошибочное значение одним событием, без зависимости от фильтрации отдельных нажатий клавиш браузером. При этом проверяются реальные обработчики и сообщения приложения; состояние React вручную не изменяется.

Первый запуск новых тестов на исходной реализации выявил 13 ошибок: пустые поля автоматически превращались в ноль, отрицательные и дробные значения молча отбрасывались, а сообщение о нулевой длительности не отображалось при обычном вводе. Два теста допустимых границ уже проходили. В `TimerView.tsx` добавлены хранение редактируемых значений, проверка обязательности и диапазона, связанные с полями сообщения и блокировка запуска до исправления. В прежних тестах взаимодействий очищенные поля теперь явно заполняются нулём, если это часть корректной длительности.

| Ошибка → исправление → запуск      | В Minutes передано `60`, затем пользователь заменяет значение на `1`    | Видно сообщение о диапазоне и заблокирован Start. После исправления сообщение исчезает, запускается `1:00` и появляется запись Recents.                | 1             |

Тестовые данные подставляются на границе существующего источника данных: через `localStorage.setItem`. Ошибки чтения и записи имитируются `vi.spyOn(Storage.prototype, ...)`. Компоненты, состояние React и логика таймера не подменяются; меню Prototype preview не используется.

Ошибки хранилища сейчас обрабатываются без отдельного сообщения: приложение продолжает работу с пустым списком или данными в памяти. Видимое состояние ошибки проверяется на ошибке ввода длительности. Ни ошибка хранилища, ни ошибка ввода не выдаются за ошибку серверного ответа.

**Граница покрытия критерия № 10:** в текущем сценарии нет асинхронной загрузки и HTTP-запросов, поэтому теста индикатора загрузки, задержанного ответа и серверных моков нет. Эти части критерия остаются неподтверждёнными. После появления API потребуются отдельные тесты ответов «успех / пустой ответ / задержка / ошибка».

jsdom проверяет DOM и поведение, но не подтверждает визуальную точность макета, адаптивность, контраст или полный аудит доступности.

## Проверка качества теста

Для проверки чувствительности теста временно удалена блокировка кнопок Recents в `TimerView.tsx`: условие `disabled={state === "running" || state === "paused"}` заменено на `disabled={false}`.

После этого тест Recents упал на проверке видимого результата: ожидаемое время `0:55` отсутствовало, поскольку нажатия Recents перезапустили таймер. Два остальных теста защиты продолжили проходить. Затем исходный код восстановлен, и все три теста снова прошли.

Для новых тестов отдельно временно отключён обработчик кнопки Cancel в `ResetDialog.tsx`. Из 11 тестов взаимодействий упали два случая закрытия этой кнопкой: диалог оставался на экране. Остальные девять случаев, в том числе закрытие Escape, прошли. Обработчик восстановлен перед итоговым запуском.

Это подтверждает, что тест обнаруживает нарушение поведения, а не только наличие кнопок в коде.

Для набора валидации временно отключён вывод сообщения об ошибке в `TimerView.tsx`. Упали все 13 случаев обязательных полей, некорректных чисел и нулевой длительности; два случая допустимых границ продолжили проходить. Вывод ошибки восстановлен перед итоговой проверкой.

Для проверки нового теста успешного результата временно отключён переход в завершённое состояние: условие `next <= 0` в `App.tsx` заменено на `next < 0`. Тест завершения упал, поскольку сообщение Time’s up не появилось. Исходное условие восстановлено перед итоговым запуском.

## Запуск и результат

```bash
pnpm install --frozen-lockfile
pnpm test
```

В окружении без команды `pnpm` после установки зависимостей тесты также запускаются через `npm test`.

Успешный запуск после восстановления защиты:

```text
Test Files  4 passed (4)

```

## Использование AI

Тесты созданы с помощью Codex по запросу пользователя: «При отправке формы исключены случайные повторные действия. Тест подтверждает, что во время ожидания повторная отправка не создаёт второй запрос — сделай под это тест».

Затем пользователь попросил добавить тесты по критерию отображения компонентов и взаимодействий: нажатий кнопок, ввода данных, открытия и закрытия диалогов. Codex добавил отдельный набор проверок, параметризовал отмену и подтверждение сброса для отсчёта и паузы и проверил чувствительность тестов временным отключением обработчика Cancel.

Codex изучил обработчик запуска и интерфейс таймера, подключил Vitest и React Testing Library, создал проверки и выполнил временное отключение защиты. После проверки скорректирована работа виртуальных часов: доставка пользовательских событий остаётся на реальных таймерах, а время отсчёта управляется тестом. Проверка Recents доработана так, чтобы сначала выполнить повторные действия и проверить оставшееся время, затем проверить блокировку кнопок.

По следующему запросу пользователя Codex добавил тесты для критерия валидации форм. Сначала они запущены на существующем коде; выявленные проблемы исправлены в обработке ввода. Затем проверена чувствительность к исчезновению сообщений об ошибках и повторно запущен весь набор тестов.

При добавлении первых двух наборов оформление и рабочая логика приложения не менялись. Набор валидации потребовал описанных выше исправлений формы; CSS и оформление остальных экранов не изменялись.

По критерию состояний Codex добавил тестовые данные для реального локального хранилища, имитацию его ошибок и проверки видимых состояний. Изменения рабочего кода для этого набора не потребовались. Отдельно зафиксировано отсутствие загрузки и API, чтобы не представлять локальные проверки как покрытие серверной интеграции.
