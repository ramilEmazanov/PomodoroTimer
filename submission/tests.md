# Клиентские тесты Pomodoro Timer

## Цель и связь с заданием

Проверки добавлены для двух критериев из [task.md](../task.md):

- **№ 7 — защита от повторных действий:** двойной клик, повторный Enter и попытки запуска Recents во время активной сессии.
- **№ 8 — отображение компонентов и взаимодействия:** главная страница, переход к таймеру, выбор и ввод длительности, нажатия кнопок, открытие и закрытие диалога сброса.

В текущем приложении нет API, отправки формы на сервер и ожидания ответа: таймер запускается синхронно в браузере. Поэтому проверяется защита от повторного запуска локального отсчёта. Эти тесты не подтверждают отсутствие второго HTTP-запроса во время ожидания сервера; для такой интеграции потребуется отдельная проверка с задержанным тестовым ответом и подсчётом запросов.

## Инструменты и подготовка

- [src/App.test.tsx](../src/App.test.tsx) — три теста реального приложения.
- [src/App.interactions.test.tsx](../src/App.interactions.test.tsx) — 11 тестов отображения компонентов и взаимодействий, включая параметризованные случаи работающего и приостановленного таймера.
- [config/vitest.config.ts](../config/vitest.config.ts) — конфигурация Vitest и окружения jsdom.
- [src/test/setup.ts](../src/test/setup.ts) — подключение DOM-проверок и очистка после тестов.
- React Testing Library и user-event — поиск элементов по доступным названиям, клики, ввод и нажатия клавиш.

Приложение рендерится в `StrictMode`. Перед каждым тестом очищается `localStorage` и выбирается светлая тема. В проверках повторного запуска подготавливаются две записи Recents: 1 и 2 минуты, затем через Timer → Input задаётся длительность 1 минута. Проверки взаимодействий начинают с пустого Recents; для теста выбора недавнего таймера отдельно подготавливаются записи на 1 и 2 минуты. Для диалогов через интерфейс задаётся длительность 30 секунд, для завершения при открытом диалоге — 3 секунды.

Используются виртуальные часы для `Date`, `setInterval` и `clearInterval`: тесты продвигают отсчёт без реального ожидания. React-компоненты и логика таймера не подменяются. Наблюдение за `setInterval` дополнительно проверяет, что при первоначальном запуске создаётся один интервал; основная проверка результата — время, отображаемое в интерфейсе.

jsdom проверяет DOM и поведение, но не подтверждает визуальную точность макета, адаптивность, контраст или полный аудит доступности.

## Проверка качества теста

Для проверки чувствительности теста временно удалена блокировка кнопок Recents в `TimerView.tsx`: условие `disabled={state === "running" || state === "paused"}` заменено на `disabled={false}`.

После этого тест Recents упал на проверке видимого результата: ожидаемое время `0:55` отсутствовало, поскольку нажатия Recents перезапустили таймер. Два остальных теста защиты продолжили проходить. Затем исходный код восстановлен, и все три теста снова прошли.

Для новых тестов отдельно временно отключён обработчик кнопки Cancel в `ResetDialog.tsx`. Из 11 тестов взаимодействий упали два случая закрытия этой кнопкой: диалог оставался на экране. Остальные девять случаев, в том числе закрытие Escape, прошли. Обработчик восстановлен перед итоговым запуском.

Это подтверждает, что тест обнаруживает нарушение поведения, а не только наличие кнопок в коде.

## Запуск и результат

```bash
pnpm install --frozen-lockfile
pnpm test
```

В окружении без команды `pnpm` после установки зависимостей тесты также запускаются через `npm test`.

Успешный запуск после восстановления защиты:

```text
Test Files  2 passed (2)
     Tests  14 passed (14)
```

## Использование AI

Тесты созданы с помощью Codex по запросу пользователя: «При отправке формы исключены случайные повторные действия. Тест подтверждает, что во время ожидания повторная отправка не создаёт второй запрос — сделай под это тест».

Затем пользователь попросил добавить тесты по критерию отображения компонентов и взаимодействий: нажатий кнопок, ввода данных, открытия и закрытия диалогов. Codex добавил отдельный набор проверок, параметризовал отмену и подтверждение сброса для отсчёта и паузы и проверил чувствительность тестов временным отключением обработчика Cancel.

Codex изучил обработчик запуска и интерфейс таймера, подключил Vitest и React Testing Library, создал проверки и выполнил временное отключение защиты. После проверки скорректирована работа виртуальных часов: доставка пользовательских событий остаётся на реальных таймерах, а время отсчёта управляется тестом. Проверка Recents доработана так, чтобы сначала выполнить повторные действия и проверить оставшееся время, затем проверить блокировку кнопок.

Оформление и рабочая логика приложения при добавлении тестов не изменялись.
